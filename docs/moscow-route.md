# Москва: МКАД / МСД

Оформление основного полотна МСД: [область, проверки и ограничения](msd-road-polish.md).
Материалы, метрическая разметка, согласованные дорожные сечения и дорожная
инфраструктура применяются к МСД и связанным рампам; МКАД остаётся черновым.

## Текущий подход: ручная доводка по референсам

Общий импорт сохраняется как черновой layout. Вместо очередной автоматической
перестройки всей сети дорабатываем последовательные участки по кадрам маршрута
и спутниковому виду. Первый участок: [0–1,94 км от старта](moscow-section-01.md).
Внесена первая локальная правка: однополосный въезд `1207836341`; магистраль
остаётся трёхполосной. Привязка визуальная, ширина и высоты не обследованы.

Ручные поправки хранятся в `data/moscow/manual-edits.json` отдельно от генератора:
стабильный OSM ID, исправленные теги или координаты `[east,up,south]` в метрах,
обоснование и URL источника. Они применяются к стандартной карте до построения
полотна, не изменяют сырой OSM-кэш и сохраняются при повторной генерации.
Несуществующий ID или некорректное значение дают явную ошибку. Перед геометрическими
изменениями нужны локальные проверки стыков/зазоров; тесты не заменяют сверку кадров.

Проверки первого прохода: 1097 тестов успешно, 8 пропущено; типизация и сборка
успешны. Полная визуальная приёмка первого участка ещё не выполнена.

Последний этап: [аудит геометрии и оставшиеся проблемы](moscow-geometry-audit.md).
Продольные переломы сглажены на всей импортированной сети, включая общие узлы
разветвлений; добавлены физические границы по полотнам выбранного движения.
После сглаживания runtime-аудит оставляет 40 подозрительных пар без общего
конечного узла рёбер (36 с недостаточным абсолютным зазором по критерию аудита).
Полная приёмка развязок и полный проезд не выполнены.
Проверка полной ширины выявила нерешённые конфликты: успешная проверка осей,
описанная ниже, не означает приёмку всех развязок.

## Обновление: встречные направления и развязки

Текущее состояние заменяет описание плоского кандидата ниже (оно сохранено как история).
`scripts/build-moscow-network.py` строит `data/moscow/network.json` из исходного кэша:
2618 OSM ways, включая 505 участков съездов. Импортируются реальные отдельные
встречные проезжие части; на обычных двусторонних дорогах создаются два направления
с правосторонним смещением между узлами. В узлах таких дорог пока упрощённые общие
горловины, без полной геометрии перекрёстков и запретов поворота.

Охват: 200 м от маршрута, полные цепочки примыкающих `_link`, подходы основных дорог
до 800 м от узлов; OSM ways сохраняются целиком. Это не гарантия полноты данных OSM
или покрытия каждой развязки до любого удалённого конца. Рёбра обрываются на границе
импорта без выдуманных возвратных рамп. Суммарная направленная длина около 605 км
включает встречные стороны и примыкающие дороги, а не длину исходного кольца.

Высоты — инженерная аппроксимация относительных OSM layers (8 м / уровень),
с распространением подъездов по связности при уклоне 6%. Взаимодействие подъёмов и
спусков допускает до 12%. Проверены 495 пересечений осей без общего узла: для всех
разных уровней обеспечен зазор >=6 м. Дорожные края, ширина пролётов, опоры и
тоннельные оболочки требуют отдельной проверки; проверка осей не гарантирует
отсутствие всех пересечений трёхмерных конструкций. Реальные высоты не измерены.

Пересобрать сеть: `python3 scripts/build-moscow-network.py`.
Повторно пройдены типизация, сборка и профильные тесты. Браузерный вход проверен;
полный проезд расширенной сети не выполнен.

## Текущий результат

Отдельный **плоский кандидат маршрута по OSM** в существующем Three.js sandbox:

```sh
npm run dev
```

Открыть `/network.html?layout=moscow`. WASD / стрелки — движение, R — возврат,
F — свободная камера. Онлайн для этого кандидата намеренно не подключён.
Основное меню, Highway, Miami и существующая карта залива не заменены.

Это основа для сверки, **не готовая достоверная копия маршрута**. Все высоты пока
одинаковы, нет реального окружения, встречного направления и боковых ответвлений.
Мосты и тоннели сохраняются в исходных тегах, но ещё не воспроизведены в 3D.
Пересечения не создают связей графа; визуальное наложение плоских дорог возможно.
OSM-полилинии пока не сглажены: изломы видны и требуют геометрической доработки.
Старт на дороге технический, он не обозначает существующую парковку.

## Данные и воспроизведение

- `data/moscow/roads.osm.json`: исходный ответ Overpass, геометрия и ID узлов/дорог.
- `data/moscow/route.json`: направленный маршрут, OSM way ID, теги, координаты,
  происхождение данных, ошибки привязки и длины этапов.
- `scripts/import-moscow-route.py`: импорт и расчёт кандидата; Python standard library.
- `src/network/moscow.ts`: перевод широты/долготы в локальные метры, дробление на
  короткие дорожные рёбра, подключение к существующим симуляции и визуализации.

Офлайн-пересчёт из сохранённых данных:

```sh
python3 scripts/import-moscow-route.py
```

Явное обновление исходных данных:

```sh
python3 scripts/import-moscow-route.py --refresh
```

## Несовпадение с Яндексом — открытая проверка

Точки из ссылки: 55.576894,37.616692 → 55.746178,37.738748 →
55.710893,37.836291 → 55.576888,37.617271.

Кандидат рассчитан по направленным OSM-связям с предпочтением магистралей.
Он учитывает oneway и базовые запреты доступа, но **не учитывает turn-restriction
relations, временные ограничения и всю семантику автомобильного роутинга**.
Ближайшие узлы могут принадлежать не той проезжей части. Это не обещание законного
или совпадающего с Яндексом навигационного маршрута.

Получено 59,446 км против примерно 55 км на пользовательском скриншоте.
Длины этапов: 23,182 / 9,426 / 26,780 км, плюс 58 м реального OSM-пути для
замыкания между близкими, но разными начальной и конечной точками.
Ошибки привязки: 12,8 / 12,7 / 38,9 / 10,9 м.
Следующий этап — наложить кандидат на референс и сверить направления, съезды,
точки разворота; затем выбрать и проработать участок 1–2 км.
Нельзя подгонять длину масштабированием всей геометрии.
