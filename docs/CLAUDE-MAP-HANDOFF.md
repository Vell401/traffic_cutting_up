# Передача карты МСД — промпт для Claude Code

Скопируй следующий блок в Claude Code из корня клонированного репозитория.
Целевая ветка передачи: `handoff/msd-map-realism`.

```text
Ты работаешь в Claude Code в репозитории traffic_cutting_up. Твоя задача —
максимально приблизить первые 1942,3 м маршрута МСД к реальной дороге,
включая окружение, а не только дорожное полотно. Работай в отдельной ветке.
Используй инструменты, браузер и при необходимости субагентов для независимых
задач. Не считай зелёные тесты доказательством визуальной достоверности.

КОНТЕКСТ И ГРАНИЦЫ
- Стек: TypeScript, Three.js, Vite, Vitest; это существующий автосимулятор,
  не новый проект. Не заменяй физику машин и сетевой протокол.
- Дорабатываем 0–1942,3 м: узел11191288649 →7566321589. Старт
  55.5769236,37.6164958; конец55.5933855,37.6206154. Технический спавн
  немного дальше начала; не переносить его молча.
- Основной маршрут:1207836341 →809185810 →809185809 →809185806(часть).
  Последнее редактируемое forward-ребро osm:809185806:1:3;
  osm:809185806:1:4 — неизменяемый буфер продолжения.
- Нужны встречные полотна809185811/809185812/809185807, нижняя петля
  809185783, первый съезд809185786 и связанный контекст. Съезд имеет тег
  tertiary, не _link: существующий msdCorridor его автоматически не оформляет.
- В отличие от предыдущего прохода, окружение ВНУТРИ ЭТОГО пилота входит
  в задачу: рельеф, насыпь/выемка, опоры и низ мостов, железная дорога,
  здания/промобъекты, трубы, тротуары/бордюры, зелень, освещение, экраны,
  дорожные знаки и ограждения — только после проверки реальных референсов.
  Не оформляй весь город, остальную МСД или МКАД.

КАК ВОССОЗДАВАТЬ
1. Запусти карту и зафиксируй исходные виды. Раздели первые2км на контрольные
   зоны: старт/кривая рампы, слияние287м, подход, мост1334–1486м,
   съезд1576м, конец1942м. Сначала составь таблицу доказательств для каждой.
2. Спутник используй для планового положения осей, краёв, окружения и сооружений;
   панорамы/дорожные фото — для числа полос, разметки, типа ограждений,
   бордюров, экранов, знаков, материалов и силуэта окружения.
   Для записи: URL, дата изображения если доступна, координата/направление
   камеры, интервал километража, наблюдение, уверенность, применённая правка.
   Проверяй разные даты: не собирай несовместимые этапы строительства в один вид.
3. Доводи зоны последовательно до принятого результата. Первое слияние уже
   переработано; следующий съезд пока имеет старую ломаную разметку и не получил
   уникальную поверхность. Не исправляй это скрытием объектов или depth offset.
4. Делай реальную непрерывную геометрию поверхностей, обочин и горловин.
   Не накладывай независимые полные ribbons друг на друга. Не заполняй
   выпуклой оболочкой настоящий островок/пустоту. Разметку и барьеры согласуй
   с той же поверхностью. Высотные пересечения без общего узла НЕ являются съездами.
5. Текущие ширина11,3м и мостовая отметка8,2м — инженерные приближения,
   не геодезия. Не сохраняй их догматически, если референсы доказывают другое;
   меняй с совместной проверкой соседних полотен, реальных треугольников,
   габаритов и непрерывности. Полосность рампы1 — локальная визуальная гипотеза.
6. Окружение моделируй по привязанным объектам и силуэтам, а не случайными
   домами/деревьями. Зафиксируй конкретную область вокруг пилота по видимости
   с дороги. Не скачивай/не публикуй чужие фотографии, спутниковые текстуры
   или модели без подходящих прав; используй изображения как референсы,
   собственные материалы и лицензированные ассеты с указанием происхождения.
7. Координаты — метры, восток+X/север−Z, projectMoscow в moscow.ts;
   без масштабирования всей карты. Опубликованные points и geometry-кэши
   нельзя мутировать после выборки sampleEdge. Сохраняй граф и доступность
   всех реальных движений; меняй исходное OSM отдельно от ID-keyed правок.

ИЗВЕСТНЫЕ ЛОВУШКИ
- Обычные1-in/1-out seam-тесты не ловят перекрытия реальных развязок.
- junctions.ts объединяет границы для движения, не создаёт видимую union-поверхность.
- Глобальный solver высот создавал искусственные холмы; не повторяй
  бесконтрольное глобальное сглаживание ради одного узла.
- Повторное сужение всего ребра по одной точке давало скачки ширины.
- Цикл разметки ранее зависал из-за численной погрешности длины на конце
  ребра и исчерпывал4ГБ памяти. Сохраняй регрессию завершения цикла.
- Причина больших серых прямоугольников с прежних скриншотов не установлена:
  воспроизведи/локализуй, не объявляй победу без проверки.
- Часть документации историческая; не выдавай старые отчёты за свою проверку.
```
